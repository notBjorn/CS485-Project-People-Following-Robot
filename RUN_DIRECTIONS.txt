CS485 People-Following Robot - Run Directions
==============================================
ROS 2 Jazzy + Gazebo Harmonic + RViz2, simulated TurtleBot 4.
All commands are run from the CS485-Project folder.


FIRST-TIME SETUP (once per machine)
-----------------------------------
1. Install the TurtleBot 4 simulator packages (run in a normal terminal so
   sudo can ask for your password):

     sudo apt update
     sudo apt install -y ros-jazzy-turtlebot4-simulator ros-jazzy-turtlebot4-desktop ros-jazzy-teleop-twist-keyboard

2. Build the workspace:

     ./scripts/build.sh


RUNNING THE SIMULATION
----------------------
Terminal 1 - Gazebo + TurtleBot 4 + RViz:

     ./scripts/launch_sim.sh

   Startup takes a while. Wait until the robot appears in Gazebo and RViz
   opens before moving on.

Terminal 2 - drive the robot with the keyboard:

     ./scripts/launch_teleop.sh

   Keep this terminal focused while pressing keys:
     i = forward    , = backward    j / l = turn left / right
     k = stop       q / z = faster / slower


MAPPING AND NAVIGATION
----------------------
Navigation needs a saved map of the world. warehouse, maze and depot already
have maps (installed with the TurtleBot 4 packages); box_room and
simple_colored_warehouse each need one made once.

Making a map (SLAM):
  Terminal 1:   ./scripts/launch_slam.sh                (add world:=... for other worlds)
  Terminal 2:   ./scripts/launch_teleop.sh              drive around until the map in RViz is complete
  Terminal 3:   ./scripts/save_map.sh box_room          name it after the world
  Then stop everything (Ctrl+C) and run:  ./scripts/build.sh
  The map is saved in src/people_follower/maps/ - commit it so the team has it.

Navigating on the map:
  Terminal 1:   ./scripts/launch_nav.sh                 (add world:=warehouse etc.)
  In RViz:      "2D Pose Estimate" = tell the robot where it is
                "Nav2 Goal"        = click a spot to send the robot there

Automated navigation (no clicking):
  Terminal 1:   ./scripts/launch_nav.sh
  Terminal 2:   ./scripts/launch_nav_node.sh
                The node docks, sets its starting pose, waits for Nav2, undocks
                and drives to the goal. Choose the goal with:
                ./scripts/launch_nav_node.sh -p goal_x:=3.0 -p goal_y:=-2.0
                Node parameters: initial_x, initial_y, initial_direction (degrees),
                goal_x, goal_y, update_period (s), resend_distance (m)


OPTIONS FOR launch_sim.sh
-------------------------
  world:=box_room      empty 10 m x 10 m room (default)
  world:=simple_colored_warehouse    30 m x 24 m warehouse with colored boxes
  world:=warehouse     TurtleBot 4 stock worlds: warehouse, maze, depot
  rviz:=false          skip RViz
  x:=1.0 y:=-2.0 yaw:=1.57    starting pose of the robot
  model:=lite          TurtleBot 4 Lite (no camera - not useful for following)
  slam:=true           build a map (same as launch_slam.sh)
  localization:=true   AMCL on the saved map for the world
  nav2:=true           Nav2 path planning (use with localization:=true)
  map:=/path/to/map.yaml    use a specific map instead of <world>.yaml

  Example:  ./scripts/launch_sim.sh world:=maze rviz:=false


STOPPING
--------
Press Ctrl+C in each terminal. If Gazebo hangs, close it and check that
nothing is left running before relaunching:

     pgrep -af "gz sim|parameter_bridge|rviz2"


AFTER CHANGING CODE
-------------------
  - Edited an existing Python file: no rebuild needed (symlink install).
  - Added a new file, world, launch file, or node entry in setup.py:

     ./scripts/build.sh


CHECKING SENSORS (in another terminal)
--------------------------------------
     source scripts/env.sh
     ros2 topic list
     ros2 topic echo --once /scan --field header
     ros2 topic hz /oakd/rgb/preview/image_raw

  Key topics:
     /scan                         LiDAR (sensor_msgs/LaserScan)
     /oakd/rgb/preview/image_raw   camera image (sensor_msgs/Image)
     /oakd/rgb/preview/depth       depth image (sensor_msgs/Image)
     /odom                         odometry (nav_msgs/Odometry)
     /cmd_vel                      drive commands (geometry_msgs/TwistStamped)


TROUBLESHOOTING
---------------
  - "Workspace not built yet": run ./scripts/build.sh.
  - "Package 'people_follower' not found": run ./scripts/build.sh.
  - "No map found for this world": make one (see MAPPING AND NAVIGATION) or
    pass map:=/path/to/map.yaml.
  - The robot doesn't move in Nav2 / RViz shows no map: set "2D Pose Estimate"
    in RViz, or check the node's initial_x / initial_y match where it spawned.
  - No topics show up: make sure every terminal uses the scripts (or runs
    "source scripts/env.sh") so they share ROS_DOMAIN_ID=30.
  - Everything is slow / camera updates rarely: the simulation is limited
    by the computer's graphics card. Close other programs, use rviz:=false,
    or run on a faster machine.
  - Warning "Desired controller update period ... faster than the gazebo
    simulation period": appears with the stock TurtleBot 4 worlds too; it can
    be ignored for now.
